# 작업물 공개 관리 화면 — 켜는 순서와 쓰는 법

이 문서 하나만 따라 하시면 됩니다. 위에서 아래로 한 번만 하면 끝나는 일(①②③)과,
매번 쓰는 일(④⑤)이 나뉘어 있습니다. 마지막 ⑥은 **이 기능으로도 안 되는 것**입니다 — 미리 알고 계셔야 합니다.

준비물은 두 개입니다: **Supabase 대시보드**(데이터가 사는 곳)와 **Vercel 대시보드**(사이트가 사는 곳).
둘 다 형 계정으로 로그인해서 웹 화면에서만 하시면 되고, 명령어를 치실 일은 ③ 한 줄뿐입니다.

## ① 먼저: 표 세 개 만들기 (Supabase, 한 번만)

지금은 「어느 작업물을 공개할지」를 적어 둘 자리가 아직 없습니다. 그 자리를 만듭니다.

1. https://supabase.com/dashboard 에 로그인 → 이 사이트의 프로젝트를 고릅니다.
2. 왼쪽 메뉴에서 **SQL Editor** → **New query**.
3. 이 저장소의 파일
   `supabase/migrations/20260916120000_portfolio_state.sql`
   을 열어 **내용을 전부 복사**해서 붙여 넣습니다.
4. 오른쪽 아래 **Run** 을 누릅니다. 초록색으로 성공이 뜨면 끝입니다.

무엇이 만들어지나요 — 표 세 개입니다.
- `portfolio_state` : 작업물 하나당 한 줄. 공개 / 링크 전용 / 비공개.
- `portfolio_state_log` : 누가 언제 무엇을 바꿨는지. **지우거나 고칠 수 없습니다**(나중에 확인용).
- `portfolio_flags` : 「제안 시안 전부 내리기」 같은 한 번에 끄는 스위치.

> 이 SQL 은 여러 번 실행해도 안전합니다(이미 있으면 그냥 넘어갑니다).
> 표를 만들기 전에도 사이트와 관리자 화면은 정상으로 뜹니다 — 다만 그동안 **제안 시안은 자동으로 내려가 있고**
> 관리자 화면의 저장 버튼이 잠겨 있습니다.

## ② 그다음: 값 세 개 넣기 (Vercel, 한 번만)

Vercel 대시보드 → 이 프로젝트 → **Settings** → **Environment Variables** 에서 세 개를 추가합니다.
셋 다 **Production** 에 체크하시고, 넣은 뒤에는 반드시 **Redeploy**(다시 배포) 를 눌러야 적용됩니다.

| 이름 | 무엇 | 어디서 구하나 |
|---|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | 서버가 표를 읽고 쓰는 열쇠 | Supabase 대시보드 → **Project Settings** → **API Keys** → `service_role` 값 복사 |
| `ADMIN_PASSCODE` | 관리자 화면 로그인 비밀번호 | 형이 직접 정합니다. **16자 이상**, 다른 곳에서 쓰는 비밀번호와 다르게 |
| `ADMIN_SESSION_SECRET` | 로그인 쿠키에 서명하는 값 | 아무 긴 무작위 문자열. 만드는 법은 아래 |

무작위 값 만드는 법 (컴퓨터에서 한 번):

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

**주의 세 가지**
- `service_role` 키는 **절대 남에게 보이면 안 됩니다.** 이 키 하나로 데이터베이스 전체를 만질 수 있습니다.
  카톡·메일로 보내지 마시고, Vercel 화면에만 넣으세요. (저장소는 공개라 코드에 적으면 안 됩니다.)
- `ADMIN_PASSCODE` 를 바꾸면 **기존 로그인이 전부 풀립니다.** 휴대폰을 잃어버렸을 때는 이 값만 바꾸면
  그 휴대폰의 로그인이 즉시 무효가 됩니다. (그게 이 값을 바꾸는 이유입니다.)
- 셋 중 하나라도 없으면 관리자 화면이 **「서버 설정 오류입니다」** 라고 크게 알려 줍니다.
  조용히 넘어가서 「눌렀는데 안 내려갔다」가 되는 일은 없습니다.

선택 사항: `ADMIN_VERIFY_BASE_URL` 에 `https://taemun.net` 을 넣어 두면
관리자 화면의 「확인」이 항상 운영 주소를 재게 됩니다(안 넣어도 알아서 찾습니다).

## ③ 확인: 남이 이 표를 볼 수 없는지 (컴퓨터에서 한 줄, 한 번만)

이 사이트의 **공개 키**는 누구나 볼 수 있습니다(브라우저에 그대로 나갑니다).
그 공개 키로 표가 열리면 안 됩니다. 아래를 그대로 복사해 붙여 넣고 **숫자만** 보세요.

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  -H "apikey: sb_publishable_MBPx3nAIgmMPeBrhY41BtQ_Y2PI2w5p" \
  "https://xqseomobgscamtchktki.supabase.co/rest/v1/portfolio_state?select=slug"
```

- **401 · 403 · 404 중 하나가 나오면 정상입니다.** (막혀 있다는 뜻)
- **200 이 나오면 잘못된 것입니다.** ①의 SQL 을 끝까지 다 실행하지 않았을 가능성이 큽니다 —
  SQL 파일 아래쪽의 `REVOKE …` 부분까지 포함해 다시 한 번 실행해 주세요.

> Supabase 대시보드에서 표가 보이는 것은 정상입니다. 대시보드는 관리자 권한으로 보는 것이라
> 「남이 볼 수 있는가」의 답이 아닙니다. 그래서 위처럼 **공개 키로 직접** 찔러 봐야 합니다.

## ④ 첫 로그인과 첫 리허설 (급하지 않을 때 미리 한 번)

항의 전화를 받은 그 순간에 처음 해 보시면 안 됩니다. 조용할 때 아래를 한 번 그대로 해 보세요. 3분이면 됩니다.

1. 휴대폰 브라우저에서 **`taemun.net/admin`** 으로 들어갑니다.
2. ②에서 정한 비밀번호를 넣고 로그인합니다. → **이 주소를 홈 화면에 추가**해 두세요(급할 때 1초라도 빠릅니다).
3. 목록 맨 위에 **제안 시안**(실존 업체 이름이 붙은 것)들이 모여 있습니다. 하나를 골라 **「비공개」**를 눌러 봅니다.
4. 그 줄의 **「이것만 확인」**을 누릅니다. → 「막힘」이라고 나오면 성공입니다.
5. 같은 줄의 **「미리보기」**를 눌러 실제로 안 열리는지 눈으로 봅니다(「공개가 종료되었습니다」 화면이 나옵니다).
6. 다시 **「링크 전용」**으로 되돌려 놓습니다(또는 **「직전 상태로」** 를 누릅니다).

세 가지 상태의 뜻:

| 버튼 | 목록(홈·포트폴리오) | 주소를 아는 사람 |
|---|---|---|
| **공개** | 보입니다 | 열립니다 |
| **링크 전용** | 안 보입니다 | **열립니다** (영업용으로 보낸 링크는 살아 있습니다) |
| **비공개** | 안 보입니다 | 막힙니다 |

> **「링크 전용」은 숨기는 것이지 막는 것이 아닙니다.** 항의가 온 시안은 반드시 **비공개**로 하세요.

## ⑤ 항의 전화가 왔을 때 (시계 기준)

| 시각 | 할 일 |
|---|---|
| 0초 | 휴대폰에서 `taemun.net/admin` → 로그인(대개 이미 로그인돼 있습니다) |
| 10초 | 맨 위 빨간 **「제안 시안 전부 내리기」** → **「네, 전부 내립니다」**. 어느 회사인지 찾을 필요가 없습니다 |
| 20초 | 화면에 「전부 내려가 있습니다」가 뜨는지 확인. **이 순간부터 링크는 이미 막힙니다** |
| 30초 | **「전부 확인」** 을 눌러 둡니다(10초쯤 걸립니다). 「전부 설정대로입니다」가 나오면 끝난 것입니다 |
| 1분 | 전화기에 대고: 「방금 내렸습니다」 라고 말씀하셔도 사실입니다 |

**전화 중에 이것만 기억하세요**
- **링크는 즉시** 막힙니다.
- **목록(홈·포트폴리오)에서 이름이 사라지는 데는 최대 20초** 걸립니다.
  그래서 내린 직후에 홈을 새로고침하면 회사 이름이 **아직 보일 수 있습니다** — 고장이 아닙니다. 20초 뒤 다시 보세요.
  (다시 누르지 마세요. 한 번이면 됩니다.)

상대가 「한 곳만 내려 달라」고 하면, 전부 내린 뒤 조용해지고 나서
그 회사 줄만 **비공개**로 두고 맨 위 **「다시 올리기」**로 나머지를 되살리면 됩니다.

실수로 눌렀을 때: 같은 자리의 **「다시 올리기」**, 또는 각 줄의 **「직전 상태로」**(5분 안).
혹시 **「데모 전부 내리기가 켜져 있습니다」** 라는 빨간 줄이 보이면 그 옆 **「데모 전부 다시 올리기」**를 누르세요.

## ⑥ 이 기능으로도 안 되는 것 (미리 알고 계셔야 합니다)

내리면 **우리 서버에서** 안 나갑니다. 하지만 이미 밖으로 나간 것까지 지울 수는 없습니다.

1. **카카오톡·문자에 남은 미리보기** — 예전에 링크를 보냈다면 그 대화방의 제목·그림은 카카오가 저장해 둔 것이라
   우리가 지울 수 없습니다. 링크를 누르면 「공개가 종료되었습니다」로 갑니다.
2. **구글·네이버 검색 결과** — 제안 시안은 처음부터 검색에 안 올라가게 막아 두었지만, 혹시 남아 있다면
   사라질 때까지 며칠 걸립니다. 우리가 당장 지울 수 없습니다.
3. **상대가 이미 열어 둔 탭, 저장해 둔 그림·PDF, 찍어 둔 화면** — 회수할 방법이 없습니다.
4. **이미 한 번 열린 이미지 주소** — 그림 파일도 같이 막히게 해 두었지만(내리면 404),
   상대 휴대폰에 남아 있는 것은 어쩔 수 없습니다.

그래서 **비공개로 내리는 것과 별개로**, 상대에게 「내렸습니다」라고 말로 알리는 것이 가장 확실합니다.

## 안 될 때 보는 곳

| 화면에 뜨는 말 | 뜻 | 할 일 |
|---|---|---|
| 「서버 설정 오류」 | 열쇠(`SUPABASE_SERVICE_ROLE_KEY`)가 없습니다 | ② 다시. 넣은 뒤 **Redeploy** 했는지 확인 |
| 「상태를 읽지 못했습니다」 + 표 이야기 | 표를 아직 안 만들었습니다 | ① 다시 |
| 「상태를 읽지 못했습니다」 + 느리다는 이야기 | 데이터베이스가 잠깐 느립니다 | 배너의 **「다시 시도」** 를 한 번 |
| 「로그인이 풀렸습니다」 | 30일이 지났거나 비밀번호를 바꿨습니다 | 다시 로그인 |
| 「가짜 상태로 읽는 중입니다」 | 개발용 장치가 켜져 있습니다 | 운영 화면이면 Vercel 에서 `PORTFOLIO_STATE_FIXTURE` 를 지우세요 |

**데이터베이스가 죽어도 사이트는 살아 있습니다.** 그때는 제안 시안이 **자동으로 내려가고**(안전한 쪽),
샘플과 운영 중 서비스는 그대로 보입니다. 즉 「장애 = 회사 이름이 노출」은 일어나지 않습니다.

## ⑦ 관리대장 P1b — 「오늘」 화면·다음 할 일·아침 문자·접속기록·자동 파기 (2026-09-19)

관리자 화면에 **오늘 · 문의 · 작업물 · 설정** 네 칸이 생겼습니다(휴대폰에서는 아래 탭). 켜는 순서는 **반드시 이 순서**입니다.

> **순서: ① SQL(아래 1) → ② Vercel Production 에 `CRON_SECRET`(아래 2) → ③ 코드 올리기(push).**
> SQL 을 먼저 돌려도 지금 떠 있는 옛 관리자 화면은 그대로 돕니다. 그 사이에 옛 화면에서 문의 상태를 「계약」으로
> 바꿔도 괜찮습니다 — 상태가 바뀌면 데이터베이스가 스스로 보관 근거를 맞춥니다(아래 4의 「계약」 설명).

### 1. 표·함수 만들기 (Supabase, 한 번만 — **코드를 올리기 전에**)

1. Supabase → **SQL Editor** → **New query**.
2. `supabase/migrations/20260919120000_admin_crm_p1.sql` 내용을 **전부** 붙여 넣고 **Run**.
   스크립트 전체가 한 덩어리라, 중간에 오류가 나면 아무것도 바뀌지 않고 전부 되돌아갑니다.
3. 파일 맨 위 주석의 **확인 쿼리 1~5** 를 하나씩 돌립니다. 특히
   `select key, value from public.crm_settings order by key;` 에서 `purge_selftest` 가 **`ok …`** 로 시작해야 합니다.
   `fail …` 이면 그 줄을 그대로 가온에게 보내 주세요.

> 코드가 먼저 올라가면 문의 목록이 새 칸을 못 찾아 「목록을 읽지 못했습니다」 가 뜹니다(작업물 화면·「전부 내리기」는 그래도 됩니다).

### 2. 아침 문자 열쇠 넣기 (Vercel, 한 번만)

Vercel → Settings → Environment Variables → **`CRON_SECRET`** 을 **Production** 에만 추가합니다. **코드를 올리기 전에** 넣어 두면
코드가 올라가면서 같이 적용되니 따로 Redeploy 할 필요가 없습니다(코드를 먼저 올렸다면 넣은 뒤 Redeploy).
값은 아무도 모르는 긴 글자(32자 이상 무작위)면 됩니다. Vercel 이 이 값을 머리글에 붙여 매일 아침 `/api/cron/digest` 를 부릅니다.

- 없으면 문자가 **나가지 않습니다**(설정 화면에 노란 줄로 알려 줍니다). 아무나 주소를 불러 형에게 문자를 보내게 만들 수 없게 하려는 것입니다.
- 시각은 `vercel.json` 의 `30 23 * * *`(UTC) = **매일 아침 8시 30분(KST)**. 무료(Hobby) 플랜은 그 시간대 안 아무 때나 한 번 돕니다 — **「매일 아침 8시대」** 로 보시면 됩니다.
- 문자에는 **숫자만** 들어갑니다(지남 2 · 오늘 1 · 새 문의 1 …). 고객 이름·연락처·할 일 내용은 넣지 않습니다. 챙길 것이 없는 날은 보내지 않습니다.
- 같은 날 두 번 가지 않습니다. 보내기 **전에** 데이터베이스에서 그날 몫을 먼저 차지하므로(`crm_claim_digest`), 예약 실행과
  Vercel 화면의 수동 **Run** 이 겹쳐도 한 통만 갑니다.
- 실패한 날(문자 대행사 오류·데이터베이스 오류)은 기록에 「안 보냄 — 이유」가 남고, 원인을 고친 뒤 Vercel → Cron Jobs 에서
  **Run** 을 누르면 **다시 보냅니다**. 이미 보냈거나 「알릴 것 없음」이던 날은 Run 을 눌러도 건너뜁니다.
- 받는 번호는 접수 알림과 같습니다(`SOLAPI_ADMIN_RECEIVER_PHONE`, 없으면 사이트의 직통 번호).

### 3. 한 번 다시 로그인

이번부터 로그인할 때마다 **기기 한 줄**이 기록됩니다(설정 → 로그인한 기기). 예전에 로그인해 둔 휴대폰은
작업물 화면·「전부 내리기」는 그대로 되지만, **문의·설정 화면을 열면 「한 번만 다시 로그인해 주세요」** 가 뜹니다. 한 번 로그인하시면 끝입니다.

- 휴대폰을 잃었으면: 다른 기기에서 로그인 → 설정 → **「이 기기 말고 모두 로그아웃」**(두 번 확인). 목록에 보이는 기기는 물론,
  **목록에 안 보이는 옛 로그인(9월 19일 이 기능이 붙기 전에 로그인해 둔 휴대폰)까지** 한꺼번에 끊깁니다 — 누른 시각보다 먼저
  로그인한 기기 번호 없는 쿠키는 모두 막습니다. 지금 누른 기기는 그대로 쓰입니다. 한 대만 끊으려면 그 기기의 **「로그아웃시키기」**.
  (데이터베이스가 잠깐 안 될 때는 옛 로그인이 작업물 화면·「전부 내리기」만 열립니다 — 급할 때 막히지 않게 일부러 그렇게 둡니다.)
- 비밀번호(`ADMIN_PASSCODE`)를 바꾸면 **모든 기기가 한꺼번에** 끊깁니다(유출이 의심될 때의 최후 수단).

### 4. 개인정보 자동 파기 — 처음엔 「시험 모드」

- 매일 00시 10분(KST) 에 데이터베이스가 스스로 돕니다(Supabase pg_cron — 위 SQL 이 예약까지 합니다).
  그래서 보관기한이 새벽 3시에 끝난 문의는 그날 밤 자정을 넘긴 **00시 10분**(날짜로는 다음 날)에 지워집니다. 「오늘」 화면·아침 문자의 **파기 지연**은
  「지난 밤 실행 때 이미 기한이 지났는데 남은 것」만 셉니다(그 사이에 기한이 끝난 건은 「30일 안 예정」에 들어갑니다).
- **시험 모드(기본값)**: 아무것도 지우지 않고 「오늘 지웠어야 할 문의 N건」만 기록합니다. 「오늘」 화면·아침 문자에 **파기 지연 N (시험 모드)** 로 보입니다.
- **실행 모드**: 접수일부터 1년이 지난 문의의 **이름·연락처·이메일·내용**을 지웁니다. 접수번호·날짜·상태는 남습니다(건수 집계용). **되돌릴 수 없습니다.**
  계약한 문의(상태 「계약」)는 보관기한이 따로라 지우지 않습니다. 상태를 「계약」으로 바꾸는 순간 데이터베이스가
  스스로 보관 근거를 「계약」으로 바꿉니다(어느 화면에서 바꾸든 같습니다).
- **계약에서 되돌리면**(접수·연락함·견적 보냄) 다시 「접수일부터 1년」 규칙이 걸립니다. 문의 화면은 이때 한 번 더 묻습니다.
  이미 1년이 지난 문의라도 **7일은 남깁니다** — 잘못 누른 것을 그 안에 「계약」으로 되돌리면 아무것도 지워지지 않습니다.
- **하루에 최대 50건**(설정값)씩, 기한이 오래된 것부터 지웁니다. 더 많이 밀려 있으면 나머지는 다음 날 밤에 이어서 지우고,
  파기 기록에 「대상 N건 중 오래된 50건만 처리 — 나머지는 다음 실행」으로 남습니다. 며칠 시험 모드로 두다가 실행 모드로
  바꿔도 이렇게 며칠에 걸쳐 따라잡습니다.
- 한꺼번에 **1,000건**(또는 한도의 20배 중 큰 값)을 넘게 밀려 있으면 뭔가 잘못됐다고 보고 **아무것도 지우지 않고**
  「비정상적으로 많아 멈춤」으로 기록합니다. 이때는 가온에게 알려 주세요.
- 권장 순서: 시험 모드로 며칠 두고 설정 화면의 파기 기록(대상 건수)이 예상과 맞는지 본 뒤 → 설정 → **실행 모드로 바꾸기**(두 번 확인).
- 파기가 하루 넘게 안 돌면 「오늘」 화면 맨 위와 아침 문자에 **「파기 작업이 하루 넘게 돌지 않았습니다」** 가 뜹니다.

### 5. 접속기록

관리자 화면을 열거나 무엇을 바꿀 때마다 한 줄씩 남습니다(누가·언제·어느 화면·어느 문의). **한 달에 한 번** 설정 화면의
「접속 기록」을 훑어보세요. 최근 35일치를 먼저 숫자로 보여 줍니다.

- **로그인 N회 · 비밀번호 틀림 N회 · 오류/거절 N건**
- **처음 보는 IP** — 「로그인한 기기」 목록에 없는 IP 에서 들어온 기록. 모르는 IP 가 있으면 「이 기기 말고 모두 로그아웃」 뒤
  비밀번호를 바꿉니다.
- 줄 목록은 「최근 35일 N건 펼치기」를 누르면 보입니다(최대 1,000줄).
- 비밀번호 틀림은 누구나 로그인 주소를 두드릴 수 있어서, IP 마다 5분 안의 **첫 번째와 잠기는 번째(5회째)** 만 기록하고
  줄 목록에는 넣지 않습니다(건수로만 보입니다). 진짜 조회·변경 기록이 틀린 시도에 묻히지 않게 하려는 것입니다.

로그인·설정 기록은 3년, 나머지는 2년 뒤 자동으로 지워집니다. 기록은 고칠 수도 지울 수도 없습니다.

### 6. 프리뷰 배포에서는 관리자 화면이 막혀 있습니다

브랜치마다 생기는 미리보기 주소(`*.vercel.app`, Vercel 의 Preview)에서는 관리자 화면이 **404**, 관리자 API·로그인·아침 문자가
**503** 입니다(판정: Vercel 이 넣어 주는 `VERCEL_ENV` 가 `preview`/`development`). 비밀값을 Production 에만 둔 것과 별개로
한 겹 더 막아 둔 것입니다. 운영 주소(`taemun.net`)는 그대로 열립니다.

### 7. (개발용) 가짜 관리대장으로 화면 확인하기

표를 적용하기 전에 로컬에서 화면만 보고 싶을 때 씁니다. **운영·Vercel 에서는 켜지지 않습니다.**

```
ADMIN_CRM_FIXTURE=1
ADMIN_CRM_FIXTURE_ACK=local-verification-only
```

두 값을 로컬 개발 서버 환경에만 넣으면 데이터베이스를 읽지도 쓰지도 않고 메모리의 가짜 문의 11건(「예시 고객 N」,
`010-0000-00NN`)·기기 2대·설정(시험 모드)으로 돕니다. 서버를 다시 켜면 처음 상태로 돌아갑니다.
Vercel 에서는 무시되고(`VERCEL` 이 있으면 끔), 운영 빌드(`next build && next start`)에서는
`ADMIN_CRM_FIXTURE_ALLOW_PRODUCTION_BUILD=yes-local-next-start` 까지 있어야 켜집니다. 켜지면 서버 로그에 경고가 한 번 뜹니다.
